## 2. Security Boundaries & Trusted Computing Base (TCB)

### 2.1 The Trusted Host Controller
- The FastAPI application runs under the dedicated system user `auron` (UID 1001).
- The `auron` user belongs to the `docker` group. On Linux, Docker socket access is effectively root-equivalent with respect to container orchestration. **Security implication:** The host backend code (`backend/orchestrator.py` and `sandbox/runner.py`) constitutes the Trusted Computing Base (TCB).
- Sandbox containers **never** mount `/var/run/docker.sock`.
- Untrusted code generated by the LLM only ever executes inside the disposable sandbox containers, with zero network, non-root UID 10001, all Linux capabilities dropped, and a read-only rootfs.

### 2.2 Secrets Isolation
- Production secrets are stored in `/etc/auron/env`.
- File ownership: `root:auron`, permissions: `0640` (root read/write, auron read-only, no world access).
- The API key is injected directly into the systemd service process via `EnvironmentFile=/etc/auron/env`.
- Secrets are never logged, never returned in API receipts, never sent to the frontend, and never passed into sandbox containers.

### 2.3 Network Perimeter
- `UFW` (Uncomplicated Firewall) allows incoming traffic on ports `22` (SSH), `80` (HTTP), and `443` (HTTPS) only.
- The FastAPI application binds exclusively to `127.0.0.1:8000` (localhost only).
- Direct access to port 8000 or the Docker daemon from the public internet is blocked by default policy `deny (incoming)`.

## 3. Production Configuration Files

### 3.1 systemd Service: `/etc/systemd/system/auron.service`
```ini
[Unit]
Description=AURON AI Analysis Engine
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=auron
Group=auron
WorkingDirectory=/home/auron/auron
EnvironmentFile=/etc/auron/env
ExecStart=/home/auron/venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5s

# Security sandboxing for service process
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/home/auron/auron/data /tmp
ProtectHome=read-only

[Install]
WantedBy=multi-user.target
```

### 3.2 Caddyfile: `/etc/caddy/Caddyfile`
```caddy
{
    admin localhost:2019
}

(common_config) {
    header {
        X-Content-Type-Options nosniff
        X-Frame-Options SAMEORIGIN
        X-XSS-Protection "1; mode=block"
        Referrer-Policy strict-origin-when-cross-origin
        -Server
    }

    reverse_proxy 127.0.0.1:8000

    log {
        output file /var/log/caddy/auron-access.log {
            roll_size 50mb
            roll_keep 5
        }
        format json
    }
}

http://45.77.19.39, http://localhost, http://127.0.0.1 {
    import common_config
}

https://45.77.19.39, https://localhost, https://127.0.0.1 {
    tls internal
    import common_config
}
```

### 3.3 Log Rotation
- AURON: `/etc/logrotate.d/auron` (daily, 14 days retention, compressed).
- Caddy: `/etc/logrotate.d/caddy` (daily, 14 days retention, compressed).

## 4. Operational Runbook

### Service Management
```bash
# Check service status
sudo systemctl status auron
sudo systemctl status caddy

# Restart services
sudo systemctl restart auron
sudo systemctl reload caddy

# View live service logs
journalctl -u auron -f
journalctl -u caddy -f
```

### Health Monitoring
```bash
# Check backend health directly
curl -s http://127.0.0.1:8000/api/health | jq .

# Check through Caddy reverse proxy
curl -s http://127.0.0.1/api/health | jq .
curl -k -s https://127.0.0.1/api/health | jq .
```

### Deployment and Rollback
```bash
# Deploy latest code
bash /home/auron/auron/scripts/deploy.sh

# Rollback to previous state
bash /home/auron/auron/scripts/rollback.sh
```
